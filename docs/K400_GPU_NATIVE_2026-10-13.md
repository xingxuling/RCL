## Execution ownership

`native/gpu-runtime/rcl-stack-vm.cl` is a generic, bounded RBC interpreter.
One actual AMD `gfx1152` FP64 OpenCL work item executes numeric/Truth/Text/Sequence
instructions, recursive calls, conditional branches, sequence construction,
structural equality, scoped warrants, projected views, preserve predicates,
witnesses and foresee/realize transaction decisions. Missing state, denied
authority, invalid bytecode, unsupported features and bounded resource failures
reject instead of using a CPU VM.

The Windows native host executes the RCL-authored compiler RBC to produce
bytecode. Python strictly decodes that binary, transports pools through OpenCL,
and reconstructs GPU-produced values and transaction snapshots. Node computes
typed v2 state hashes from those returned snapshots. Hashing is explicitly
host-owned; GPU-native SHA256 and GPU-hosted compilation are not claimed.
The prior BF16 provider is reused only for ctypes OpenCL transport and AMD GPU
selection. Its original source and prior receipts remain unchanged.

The development mode was routed to `DEEP_DEVELOPMENT` by the actual local
archived DWAC four-mode router, source SHA256
`feec830b66b404c243f3bb4c3d2c66706429c670a0f4c396dee6246d5363ee44`.
That routing is advisory and owns no writes or admission decisions.

## Running and scope

```text
node scripts/run-gpu-native.mjs examples/universal-stress/genomes/governance-reactive.rcl
node scripts/run-k400-gpu.mjs --verify
npm run evidence:k400
```

The public asynchronous API is `createPortableGpuTarget()` with `compile`,
`execute`, `verifyReset` and `dispose`. This verified setup requires Windows,
Python 3, the installed AMD GPU OpenCL driver with `cl_khr_fp64`, and the checked-in
native compiler/RCL compiler RBC. `RCL_GPU_PYTHON` or `pythonPath` selects Python.
Only four builtins are supported: length, empty sequence, append and get.
Text literals/equality/length work; text concatenation, ordering and other
builtins reject. Provider calls, typed records/references and sessions reject.
The interpreter has fixed stack, frame, value, transaction and instruction
limits. The profiles prove their sealed input domains, not arbitrary-language
equivalence, another GPU/OS, parallel execution or production deployment.
