## Runtime capability

The new generic RBC interpreter executes Text allocation and operations on the
actual AMD gfx1152 FP64 OpenCL GPU. Its bounded 8 MiB UTF-8 arena preserves
retained values. Concatenation, scalar-to-Text conversion, Unicode scalar length,
character access and slicing, Text predicates, split, ASCII case conversion and
trim are device operations. Persistent Sequence concatenation is also supported.
The existing GPU interpreter, native compiler/VM and previous K400 contracts
remain byte-identical.

Number formatting reuses Apache-2.0 Ryu at pinned commit
`4c0618b0e44f7ef027ebae05d2cc7812048f7c8f`; upstream source bytes, copyright,
both offered license texts and the selected Apache license are retained. The
OpenCL adaptation uses explicit address spaces and portable integer arithmetic.
Subnormal formatting preserves the observed native C seventeen-digit fallback.
Actual GPU/native C parity tests cover 71 deterministic finite values, formatting
boundaries, computed subnormals, Unicode, persistent aliases and failure recovery.
These samples do not establish all-binary64 or all-Unicode equivalence.

A separate RCL-authored scientific-number compiler accepts decimal exponent
suffixes with an optional sign and mandatory digits. Eight native bytecode and
execution cases, five invalid syntax cases and a native C0/C1/C2 fixed point pass.
The separately generated JavaScript reference is an oracle; it owns no GPU
execution. Original/default compiler pipelines and frozen artifacts are preserved.

GPU program compilation runs the RCL compiler RBC on the native Windows host;
program execution and transaction decisions belong to the device kernel. The
host transports and hashes device-produced snapshots. There is no CPU execution
fallback. Number-from-Text, arbitrary provider calls, byte/hash builtins and GPU
whole-compiler self-hosting remain unsupported by this Text runtime. It runs one
work item; parallel throughput and a security sandbox are not claimed.

## Frozen UI acceptance

The profile uses the existing integer counter source. Each selected environment
runs twenty complete four-action baseline flows, ten sealed input cases, three
effective broken candidates and three unchanged independent repairs. All nine
gates include exact RBC comparison, source/state/history/root replay, authenticated
stale-state and authority rejection, malformed/corrupt input rejection and the
unchanged P95 compile/execute budgets of 5000/2000 ms.

Three fresh proposal-only contexts receive only the frozen mutated source and
task requirements. They return actual patches. The same three proposals replay
in the GUI/Web and Android contracts; this is three contexts, not six. Canonical
source, oracle edits and sealed tests were not supplied. This is context separation,
with no OS isolation claim.

GUI/Web uses actual Chromium DOM clicks, reload and mobile viewport checks.
Android uses actual API35 x86_64 native Views, real ADB touch, activity recreation
and process restart, with the original frozen APK. Its read-only secondary
emulator serial `emulator-5556` keeps the ongoing nineteen-backend mobile
acquisition on `emulator-5554` independent. The Android geometry contract pins
the actual 1080×2840 override and density 420; the superseded geometry draft
receives zero credit. Physical devices, offline/durable backends, public hosting
and arbitrary UI-language equivalence remain outside the profile.
