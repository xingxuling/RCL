# Complete compiler worker graphs and replica peers

Two separate frozen profiles add actual complete-compiler capabilities to existing
worker contexts. The original dataflow, replica, resident compiler and HTTP owners
retain their source and binary bindings. Both new APIs are exported from `src/index.mjs`.
Version promotion remains frozen. No hosted Actions are used.

## K319: compiler-to-VM dataflow

`createCompilerDataflowTarget` starts two actual worker threads. The compiler stage
owns a resident native compiler C ABI process and accepts the caller's compiler
artifact and source. The VM stage owns actual native program processes. The
`compileAndExecute` operation transfers the generated bytecode directly between
stages under one flow identity; its edge binds the producer request, compiler
thread and exact artifact hash. One flow may be in flight. Bad source bindings are
rejected before a native call; malformed source and corrupt compiler rejection
leave the compiler available for a healthy full generation. Both stage threads and
the native compiler exit gracefully, and program exits are independently recorded.

The [contract](../examples/universal-stress/selfhost-dataflow/general-compiler-dataflow-contract.json),
[runtime](../examples/universal-stress/selfhost-dataflow/general-compiler-dataflow-dataflow-runtime-runtime.json)
and [index](../examples/universal-stress/selfhost-dataflow/general-compiler-dataflow-runtime.json)
verify twenty supplied-artifact C0-to-C20 generations, ten sealed programs and three
effective unchanged independent repairs. Sealed programs and broken repair probes
traverse the actual linked graph. Compilation P95 is 3611.4578 ms; execution P95 is
189.3442 ms. This is a bounded local Windows graph, without an external stream,
multi-host runtime, security sandbox or whole-language release claim.

## K259: replicated compiler

`createReplicatedCompilerTarget` starts two separate authenticated loopback HTTP
workers and native compiler processes. Both consume the same caller-supplied
compiler/source snapshot. Publication requires both complete compilation results
and byte equality; program execution requires exact native result agreement.
Stopping one peer is observed through clean server/compiler exits. A subsequent
one-peer compilation completes on the survivor but cannot publish an artifact.
An actual replacement peer establishes a new compiler context, then both peers
complete a healthy full generation and identical program replays.

The [contract](../examples/universal-stress/selfhost-replica/general-compiler-replica-contract.json),
[runtime](../examples/universal-stress/selfhost-replica/general-compiler-replica-distributed-runtime-runtime.json)
and [index](../examples/universal-stress/selfhost-replica/general-compiler-replica-runtime.json)
verify twenty complete generations **on each peer**, ten sealed programs on both
peers and three effective unchanged independent repairs. Compilation P95 is
3662.1742 ms; execution P95 is 398.8845 ms. These are distinct local processes
running the same implementation, not independent implementations, a multi-host
deployment or Byzantine consensus.

## Evidence and reuse

Both retain the unchanged budgets: 300000000 instructions per native compilation,
compilation P95 at most 50000 ms and execution P95 at most 5000 ms. Each complete
generation executes 101897504 instructions and returns the pinned 297957-byte
compiler. The six new proposal-only contexts received only their exact frozen
candidates and requirements, with no canonical source, oracle edits or hidden
tests. Their raw completed replies and input hashes remain in separate
[dataflow](../examples/universal-stress/selfhost-dataflow/independent-batch.json)
and [replica](../examples/universal-stress/selfhost-replica/independent-batch.json)
batches. OS isolation is not claimed.

The stage worker extends the existing dataflow pattern and reuses the resident
native compiler. The replicated API extends the existing two-peer HTTP pattern
and reuses the dynamic resident HTTP API. Profile engine/admission headers pin
the exact HTTP donor source paths and hashes. Source-bound old owners remain intact.
DWAC's actual local four-mode router selected `DEEP_DEVELOPMENT`. Laya suggested
GPU as an advisory candidate; inspected source supported completing these existing
worker-owner gaps first. The final implementation and admission decisions remain
with Codex and the user.

The two actual API tests and twenty-six admission checks total 28 focused passing
checks. They reject rehashed forgeries involving stage/thread/native identity,
missing graph edges, source binding, backpressure, replica results, partial
publication, recovery, clean exits and missing generations. A separately exported
tracked-source tree tests both public APIs and revalidates both captured profiles.
It does not freshly reacquire the entire K400 or establish another OS/device.
The [delivery receipt](evidence/worker-selfhost/verification.json) retains these
separate scopes and the consolidated K400 result.

Use `npm run test:selfhost-dataflow` and `npm run test:selfhost-replica`.
The public methods accept `compilerFile`, `sourceFile` and optional `outputFile`:

```js
import {createCompilerDataflowTarget, createReplicatedCompilerTarget,
  compileReality} from './src/index.mjs';

const graph = await createCompilerDataflowTarget();
try {
  const source = 'reality Hello { facet value : Number = 9 + 2 }';
  // hello.rcl contains source; c1.rbc is an actual supplied compiler generation.
  const flow = await graph.compileAndExecute('c1.rbc', 'hello.rcl',
    compileReality(source).programRoot);
  console.log(flow.executed.result.state.value); // 11
  console.log(flow.edge); // actual producer/consumer artifact binding
} finally {
  await graph.dispose();
}

const peers = await createReplicatedCompilerTarget();
try {
  const compiled = await peers.compile('c1.rbc', 'hello.rcl', 'hello.rbc');
  console.log(compiled.replicaTrace.peers.map(p => p.artifactHash));
} finally {
  await peers.dispose();
}
```
